# PRD (Product Requirements Document) - 任務管理系統

## 1. 專案概述
- **背景與動機**：現代人面臨繁雜的工作與生活瑣事，常因缺乏有效的管理工具而導致遺漏重要事項或工作進度延宕。本系統旨在提供一個直覺、清晰的任務管理平台，讓使用者能輕鬆組織待辦事項、追蹤進度，進而提升效率與減輕壓力。
- **目標用戶**：需要管理個人工作進度的上班族、學生、自由工作者，以及需要進行基本專案進度追蹤的使用者。
- **核心價值主張**：簡單、直覺、高效。透過最少的操作步驟完成任務的紀錄與追蹤，幫助使用者將專注力回歸到「執行」本身。

## 2. 功能需求
系統的主要功能模組與對應的使用者故事：

1. **帳號與權限驗證**
   - 作為 **一般用戶**，我希望 **能夠註冊並登入個人帳號**，以便 **安全且私密地管理專屬於我的任務清單**。
   
2. **任務基本操作 (CRUD)**
   - 作為 **一般用戶**，我希望 **能夠新增、編輯與刪除任務**，以便 **隨時根據實際情況更新我的待辦事項清單**。
   
3. **任務狀態管理**
   - 作為 **一般用戶**，我希望 **能夠一鍵將任務標記為「已完成」或取消完成狀態**，以便 **清楚掌握目前的工作進度與還未處理的項目**。

4. **時間與優先級設定**
   - 作為 **一般用戶**，我希望 **可以為任務設定截止日期與優先級（如：高、中、低）**，以便 **我可以根據輕重緩急安排每一天的工作計畫**。

5. **任務分類整理**
   - 作為 **一般用戶**，我希望 **可以建立不同的分類項目（例如：工作、生活、學習）並將任務歸類**，以便 **有條理地組織不同領域的事項**。

## 3. 非功能需求
- **技術限制**：
  - 後端框架：使用 Python 搭配 **Flask** 框架。
  - 前端渲染：使用 **Jinja2** 模板引擎搭配基本的 HTML/Vanilla CSS 進行畫面構建。
  - 資料庫：使用輕量級的關聯式資料庫 **SQLite**。
- **效能與安全考量**：
  - 安全：具備基本的防禦機制（防範 SQL Injection, XSS 等），使用者密碼必須經過雜湊（Hash）加密後再存入資料庫（例如採用 Werkzeug 的 security 模組）。
  - 效能：回應時間應小於 500ms（內部網路環境下），以確保流暢的使用者體驗。

## 4. MVP 範圍 (Minimum Viable Product)
為了快速測試市場與驗證概念，首個版本的開發範疇劃分如下：

- **Must Have（必須具備，MVP 核心）**：
  - 使用者註冊與登入功能
  - 任務的 CRUD（新增、檢視、修改、刪除）
  - 切換任務的完成狀態
  - 任務列表展示（依建立時間排序）
  
- **Should Have（應該具備，可延後到下個迭代）**：
  - 任務截止日期與優先級設定
  - 依優先級或狀態篩選/排序任務
  - 基本的分類功能

- **Nice to Have（有了更好，未來擴充方向）**：
  - 截止日期到期提醒（如 Email 通知）
  - 圖表化顯示個人任務完成率
  - 子任務切割功能
